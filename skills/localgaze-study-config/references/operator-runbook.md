# 给零基础主试的运行步骤

如果任务包状态为 `DRAFT`，或关键问题仍是 `missing`，停在草案，不启动。

1. 复制任务包到工作目录。设备原始文件保持只读。会话/被试标识只用假名，不放姓名、邮箱或不必要的个人信息。
2. 先读任务包的中文《操作卡》。核对文件、工作表、列名、时间单位/原点、屏幕参考信息、预处理 preset、输出文件夹。任何输入与操作卡不一致时先停下，要求更新方案。
3. 创建一个新的空输出文件夹，放在原始数据目录之外。不要复用旧结果文件夹；核对输出不与任何输入重叠。
4. 在 LocalGaze 桌面程序中导入桌面 JSON。导入只会填充控件，不会运行。逐项回读会话编号、输入/映射表、时间单位、指标选项、输出目录和格式；路径字符串有效不代表文件存在。
5. 点击运行前对照屏幕/坐标事实。2560×1440 和 DPI 默认不是设备事实。确认原始 X/Y、有效性标记、时间列，以及 participant/session/trial/stimulus ID。ROI 分析还须确认 ROI 与 gaze 使用已验证的相同坐标参考。
6. 若有合成或脱敏 pilot，先按已批准方案跑一次。保存日志、产物、manifest、QC sidecar 和核对表。对照源文件 hash、行数、ID、时间范围、质量计数和预期指标。缺文件、报错、行数/键值变化、时间漂移或指标意外为空时停下。
7. 只有 pilot 通过后，才用批准参数处理正式数据；每个新 run 写入全新目录。保留配置、参数台账、转换台账、版本、文件 hash、GUI/API 入口、运行日志和 QC 汇总。
8. 统计是独立步骤。只有统计计划与环境状态标记可执行时才运行其脚本。检查估计量、区间、计数、排除、诊断、警告和错误；不得因 p 值不理想而临时换检验。
9. 失败时保留失败目录和文件，记录 `FAILED`/`NOT_RUN`、错误文本和最后成功步骤，再执行操作卡给出的下一步。不得删除或覆盖原始文件或失败证据。

每个操作步骤都必须写清：要做什么、预期看到什么、成功条件、失败现象、下一步。主试不需要自行决定统计检验。
