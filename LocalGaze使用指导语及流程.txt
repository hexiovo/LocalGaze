LocalGaze 整体使用指南
适用：当前统一桌面工作台（launch.py / 新版便携包 LocalGaze.exe）
更新日期：2026-10-02

一、启动与查看指南

便携版：完整解压新版压缩包，双击 LocalGaze.exe。保留同目录的 LocalGazeWorker.exe、ROIDrawing.exe 和 _internal 文件夹，无需另装 Python。旧版独立 EXE 不包含当前统一工作台。
源代码：在项目根目录使用已有 LocalGaze Python 环境运行 python -B launch.py。

窗口顶部的“查看整体指南”可从任何页面打开本文，也可直接点击“使用指南”页。阅读区域支持滚动、选择和复制；右下方“打开 TXT”可在系统编辑器中查看。运行任务期间仍可阅读指南。
启动或阅读指南不会启动摄像头；点击校准、采集等操作才会启动相应任务。

二、第一次使用：推荐顺序

准备设备与文件夹 → 校准并保存模型 → 使用已有模型采集 → 预处理与 QC → 分析与导出 → 检查结果状态并保留原始文件。

需要区域统计时，在分析之前绘制 ROI；只需要整体指标时可不选 ROI。
“已知目标修正”是可选步骤，首次使用可跳过。它只能估计特定条件下的偏移，不替代完整校准。
分析页可以直接分析受支持的原始数据，预处理不是强制前置步骤；建议先预处理以检查时间、有效样本及数据质量。

五个页面的分工：
• 会话与采集：会话 ID、输出位置、模型、校准、采集及可选修正。
• ROI 绘制：在目标显示器的当前画面上标注静态区域。
• 预处理与 QC：校准模型/工作簿与数据匹配，生成处理文件和质量报告。
• 分析与导出：选择单个数据文件及可选 ROI，导出指标、样本和候选事件。
• 使用指南：查看本文。

“输出位置”和“模型路径”在相关页面之间共享；切换操作后务必重新核对。预处理数据输入和分析数据输入则相互独立。成功生成唯一预处理文件时，程序会预填分析输入，仍需自己点击分析。

三、设备与被试准备

将摄像头放在靠近屏幕上方中心的位置，固定摄像头与屏幕的相对位置。让脸和眼睛清晰可见，避免背光、眼镜强反光、摄像头持续自动调焦。
选择舒适坐姿，保持校准与正式任务的距离、灯光和分辨率接近。无需强迫头部完全固定，但大幅转头、移位或更换屏幕后应重新校准。
先做一次短流程，检查文件与指标状态，再进行正式实验。该短流程只能帮助检查操作，不能替代独立精度验证。

四、建议的文件夹组织（避免把两种 XLSX 混淆）

每名参与者/每次会话建立一个文件夹。例如：

P001_session01/
    models/        校准生成 P001_session01.pkl、P001_session01.xlsx
    raw/           采集生成 P001_session01.txt、P001_session01.xlsx、P001_session01.manifest.json
    roi/           ROI 工具在此生成 ROIdata/*.xlsx
    preprocessed/  预处理文件、QC 与批次记录
    analysis/      每次分析的会话子目录和导出文件
    offset/        可选已知目标采集与修正记录

首次校准和采集均填写会话 ID：P001_session01，但分别选择 models 和 raw 作为输出位置。这使文件名对应，同时避免校准工作簿与采集工作簿发生重名冲突。

两种 P001_session01.xlsx 的用途不同：models 中的是校准工作簿；raw 中的是正式采集数据。采集使用 models 中的 .pkl；预处理优先选择 models 中的校准 .xlsx，不能选 raw 中的采集 .xlsx 作为模型。

保留同批次文件与 manifest，避免随意重命名。另一次采集应使用新名称/新目录；预处理要求对应校准文件与数据文件具有相同文件名主干（扩展名前的部分），因此复用模型时也要准备明确对应的同名校准文件，并记录其来源。不要仅修改 UI 会话 ID 就假设不同名文件能够匹配。
程序采用不覆盖策略，目标已存在时选新的输出目录或会话名。不要删除原始数据来消除冲突。

五、校准并保存模型

1. 在“会话与采集”页填写会话 ID，例如 P001_session01。
2. 输出位置选本次会话的 models 文件夹。校准保存位置由“输出位置 + 会话 ID”决定；“模型路径”不是新模型的保存路径，校准时不用填写它。
3. 默认保留 Ridge 估计器与 v2 紧凑眼部、头部特征。其他估计器在高级设置中可选，不要因训练残差较小就假定其真实精度更高。
4. 点击“校准并保存模型”，按提示注视目标。固定九点需完成三轮有效访问，每个点要通过稳定门控和样本覆盖要求。分轮按提示采用舒适的自然头部姿态；目标采样期间尽量稳定、看准目标。
5. 完成固定轮次后，后端可能询问是否进一步校准。首次建议选择“否”完成保存；确有覆盖需要时再进行补充校准。
6. 工作台完成状态与输出为准。成功会保存同名 .pkl 和校准 .xlsx。校准失败可能留下 calibration-status.json，不应把它视为可用新模型。

训练拟合残差只描述参与训练数据的拟合程度，不是独立眼动精度。换人、改变摄像头位置、明显改变坐姿或光照后重新校准。

六、正式采集

1. “模型路径”选择已成功保存的 models/P001_session01.pkl。
2. 核对会话 ID，输出位置切换至 raw 文件夹，避免与校准工作簿重名。
3. 在目标屏幕准备图片、视频、阅读页面或其他任务内容。当前工作台不自动安排刺激序列，也不自动生成可用于首注视潜伏期的刺激事件时间。
4. 点击“使用已有模型采集”。已有模型采集不会自动重训模型。按实际采集窗口提示完成任务。
5. 正常结束时，让采集窗口获得焦点并按 Escape。工作台的“取消当前任务”用于中止任务；取消或失败可能保留部分文件，不等同于正常采集完成。
6. 检查完成状态和日志。正常输出包括同名 TXT、XLSX、manifest.json。优先保留整组原始文件，后续预处理可选其中一个数据文件。

不要仅依据光标平稳判断精度。无效样本、头部特征超出训练范围等状态值得检查；范围内也不保证精度已验证。

七、可选：已知目标修正

已有模型可先运行“已知目标修正”。在高级设置中，目标 X/Y 均留空时使用模型画布中心；自定义位置需同时填写 X 与 Y，单位为屏幕像素。
选择独立输出目录与新的会话 ID，点击操作并按提示注视明确目标。程序在有界窗口中采集，只有稳定性、模型和画布绑定等条件通过才保存修正 JSON。中止或被拒绝时，原始记录可能保留，但不会生成合格修正文件。

普通采集默认不应用修正。如需使用，选择合格修正文件并显式勾选“在正式采集中显式应用此修正文件”；更换模型或画布后不能继续套用旧修正。
应用修正后，原始 X/Y 保留，另写 corrected_x_px / corrected_y_px 及相关状态。默认分析仍使用原始坐标，不能把导出的修正列当成默认分析结果或独立实测值。
偏移修正不是自动漂移追踪，也无法补偿所有头部运动和非线性误差。

八、可选：绘制 ROI（感兴趣区域）

1. 先在目标显示器上显示图片、视频或阅读页面，再打开“ROI 绘制”页。
2. 输出位置可选本次 roi 文件夹，点击“打开 ROI 绘制工具”。工具为独立屏幕叠加窗口，没有背景素材文件选择器。
3. 在绘制窗口核对目标显示器和坐标参考，按工具提示绘制、命名并保存区域。工作簿写入输出位置的 ROIdata 子目录。
4. 在“分析与导出”页选择保存的 ROI 工作簿。

ROI 是静态几何区域，适合固定布局。视频内容改变或对象移动时不会自动跟踪对象。采集与 ROI 的画布、显示器与坐标参考需要已知、已验证且兼容；未知参考不会按分辨率或 DPI 自动推断。
多个 ROI 重叠时，主命中按保存优先级确定，all_hits 记录全部命中。区域进入和离开时间是离散采样估计。

九、预处理与 QC

1. “模型路径”选本次 models 中的校准工作簿，或含对应校准文件的文件夹。
2. 数据输入选 raw 中一个 TXT 或 XLSX。初次建议单选 TXT，避免把同名 TXT、XLSX 同时作为批处理输入。
3. 输出位置选新的 preprocessed 文件夹。
4. 在高级设置确认 seconds、milliseconds 或 microseconds。新格式 elapsed_s 明确为秒；旧数据须按真实来源指定单位。
5. 点击“运行预处理与 QC”，完成后查看处理文件及报告。

匹配规则是文件名主干相同（忽略大小写），例如 P001_session01.xlsx 校准文件对应 P001_session01.txt 数据。改 UI 会话 ID 不改变匹配。一个主干出现多个校准工作簿或多个数据文件可能被拒绝；批处理应把每个主干的一份数据整理到单独输入文件夹。

批次报告状态：processed 为已处理；data_without_model 为数据找不到同名模型；model_without_data 为模型找不到同名数据；failed 为处理失败。还需查看每项具体原因，不要把批次完成等同于所有文件成功。
当前 analysis 预设不插补 gaze X/Y。保留原始观测列与新增 Pre 派生列的区别。输出目录与 raw 分开，不能以平滑或插补后的轨迹替代原始测量。

十、分析与统一导出

1. 在“分析与导出”页选择一个受支持的眼动数据文件，可选预处理后的文件，也可选原始文件。它与预处理输入独立。
2. 输出位置切换到 analysis 文件夹；需要区域指标时选择 ROI 工作簿，不需要时留空。
3. 核对时间单位。“自动识别”依赖来源字段和元数据契约，不是对任意数值的猜测。有歧义的纯数值时间应明确选择秒、毫秒或微秒。
4. 点击“分析并导出结果”，按真实日志检查是否完成。GUI 每次处理一个分析文件；多会话请逐个选择和运行。
5. 成功后使用底部“打开本次输出”菜单选择真实存在的产物。失败或取消时先看日志，不能把部分文件当成完整结果。

分析会在输出位置下建立会话子目录，通常包含：
• <会话>_summary.xlsx：指标摘要、方法/状态与相关明细。
• <会话>_samples.csv：样本与派生字段。
• <会话>_events.csv：工程规则生成的候选事件。
• <会话>_roi_hits.csv：ROI 命中记录；无可用 ROI 时不能假定已有区域指标。
• <会话>_manifest.json：输入来源、配置、产物与哈希记录。

先看 summary 中的指标值、status、reason 和 method，再看样本及事件明细。指标空值不等于零。保留 manifest 以追溯来源与配置。

十一、如何理解指标

分析结果中的 `status`、`reason` 和 `method` 应与数值一起阅读：

- `computed` 表示本次按方法得到数值；`estimated_candidate` 表示规则生成的候选；`not_observed` 表示在当前可计算记录中没有观察到候选；`not_computable` 表示缺少必要输入或条件。`null`/空值不是零，也不代表事件没有发生。
- 时间统计、有效样本和相邻有效时间差依赖可信且连续的来源时钟。接收时间（receipt time；例如 `received_monotonic_ns`）是成功读取摄像头帧的本地完成时刻，不是 sensor exposure time（传感器曝光时刻），也不等同于端到端延迟。
- 当前事件表中的 `fixation_candidate`、`fast_movement_candidate` 和 EAR 状态产生的 `blink_candidate` / `long_closure_candidate` 均为工程候选，不是经真实参与者或独立真值验证的生理分类。对应计数包括 `fixation_candidate_count`、`fast_movement_candidate_count` 与 `blink_candidate_count`。默认配置中的候选参数包括：fixation 至少 3 个样本、持续至少 0.120 秒、离散度比例 0.03；fast movement 使用每秒 1.0 个屏幕对角线的速度阈值；EAR closure 的候选时长范围为 0.050–0.500 秒。代码配置可改变这些参数，分析输出的配置和方法记录才是本次运行的依据。
- blink/closure 候选依据上游 EAR 状态及时间序列；未被独立观察的眼睑真值不能从结果中推断。快速移动候选也不等同于已验证的眼跳或角速度。
- 训练拟合残差（指标 ID 以 `calibration_fit_residual_px_` 开头）来自用于训练校准模型的数据，只能描述训练拟合；它不是独立注视精度，也不代表外部 ground truth。
- `left_iris_proxy_mean` / `right_iris_proxy_mean` 是二维 iris ring/eye-span 比值代理，单位是 ratio，不是物理瞳孔直径，更不是毫米。`iris_ratio_blink_candidate_count` 当前因缺少独立、同公式的代理基线契约而不可计算；不能把 iris ratio 当成眨眼结果。
- 静态 ROI 指标只有在 ROI 和注视坐标的 reference 已知、已验证且兼容时才可计算。未知坐标引用保留为未知，不按屏幕分辨率或显示器 DPI 猜测。
- 一些已实现统计在前提不足时可以保留为不可计算，例如 `observed_sampling_rate_hz` 等时间统计需要可信且有效的相邻时间，`time_weighted_grid_entropy_bits` 需要已知屏幕尺寸和有效带时相邻样本，`roi_primary_observed_duration_s` 及 `roi:<id>:...` 指标需要兼容且已验证的坐标引用。补齐这些既有计算所需的可靠输入后，代码才可能计算相应指标。
- 另一些指标 ID 当前只输出 `null` 与原因，没有可用计算或可靠输入来源：`visual_angle_displacement_deg`、`stimulus_first_fixation_latency_ms`、`stimulus_first_roi_entry_latency_ms`、`binocular_vergence_deg`、`physical_pupil_diameter_mm` 和 `independent_gaze_accuracy_px`。仅补入屏幕尺寸、刺激时间或其他元数据，不表示这些指标会自动变成可计算值。

十二、常见问题

• 提示文件/目录已存在：换用新的输出位置或会话名，保留旧记录。校准与采集不要共用同一输出文件夹和同一工作簿名。
• 摄像头不可用或有效样本少：确认相机未被其他程序占用、系统允许使用相机，改善光照和眼睛可见性，再尝试短流程。
• 模型加载失败：采集选择 .pkl，预处理优先选择校准 .xlsx；确认模型来自对应参与者、设备与特征契约。旧模型信息不足时重新校准更稳妥。
• data_without_model：检查文件名主干及模型路径，不要把正式采集 XLSX 误选作校准工作簿。
• 同名数据重复：输入文件夹同时有 TXT 与 XLSX 时只整理一份作为本次输入，完整原始组保留在 raw。
• 时间统计不可计算或异常：检查实际时间单位、来源时钟与缺失时间，不能通过猜单位让结果看起来正常。
• ROI 指标不可计算：核对坐标参考及兼容性，阅读 reason；不应强制缩放未知坐标的旧工作簿。
• 取消/失败后有文件：这是可能的部分记录。保留日志，后续使用新目录运行完整任务。
• “打开本次输出”不可用：本次尚无成功确认的现存输出，先查看任务状态和日志。
• 指南加载失败：保留便携包完整目录及 UTF-8 指南 TXT；程序先读取 EXE 同目录指南，缺失时回退到内置文件。

十三、普通摄像头条件下的精度与实验建议

优先改善眼睛可见性、光照和摄像头稳定性，保持校准与采集条件接近。校准时按提示覆盖自然头部姿态，每个目标采样期间保持稳定，比只增加重复帧更有意义。
默认 Ridge 与 v2 特征是建议起点。稳定门控与已知目标偏移修正可改善输入条件或特定偏移，但没有独立验证数据时不能报告精度提高的百分比或角度。
平滑可以减少显示抖动，同时增加延迟；不代表定位准确度提升。分析应保留原始坐标和无效样本状态。
头部明显移位、屏幕/摄像头移动或任务条件变化后重新校准。head_descriptor_outside_training_range 只是粗略特征范围提示，不能证明范围内精度可靠。

软件的合成数据检查、模型加载和隐藏窗口检查仅验证相应软件功能，不验证真人注视准确率、真实相机质量或独立精度。接收时间不是相机曝光时间；训练残差不是独立精度；二维 iris 比值不是物理瞳孔直径。

正式操作前的简短核对：
□ 会话 ID 明确，校准与采集输出分开，同名校准文件可对应数据。
□ 使用对应参与者和当前设备条件下的模型。
□ 摄像头、坐姿、光照与校准接近，眼睛清晰可见。
□ 时间单位有真实来源，ROI 坐标参考兼容（若使用 ROI）。
□ 保留原始数据、manifest、处理报告和分析方法/状态。
□ 以完成状态与日志判断输出，不把取消后的部分文件当成成功结果。

启动、依赖与旧组件说明见 README.md；版本和软件检查记录见 version.md。
