# 实验设计填写模板

请先填写研究设计和数据事实，再生成 LocalGaze 配置与执行材料。每个参数记录数值、单位、来源、风险和状态：`known`（已有可核实事实）、`proposed`（待研究者确认的建议）、`missing`（尚未提供）或 `not_applicable`（不适用并说明原因）。不要把示例值当作已确认设置。

## 1. 研究问题与设计

- 假名化研究编号：
- 研究问题：
- 主要结局、指标定义和时间窗：
- 主要比较、方向和估计目标：
- 实验设计：组间 / 配对 / 重复测量 / 交叉 / 嵌套 / 其他：
- 条件分配单位：被试 / 会话 / 试次 / 刺激 / 其他：
- 推断单位：
- 被试、会话、试次、刺激等 ID 字段：
- 随机化、平衡顺序、携带效应或分组规则：

## 2. 设备与采集

- 眼动设备、型号、固件和采样模式：
- 采样率及时间列名称：
- 时间单位、原点、触发源和同步时钟：
- 屏幕分辨率、物理尺寸、观看距离、坐标原点、轴方向和 DPI：
- 校准模型、校准时间及接受标准：
- 环境、姿势、照明及影响测量的因素：

## 3. 输入数据

- 原始文件位置、格式、工作表、编码、分隔符和小数格式：
- 时间、原始 X/Y、有效状态、眨眼、左右眼瞳孔列：
- 被试 / 会话 / 试次 / 刺激 / 事件字段：
- 哪个字段明确表示样本是有效实测：
- 代表性文件及其来源：
- 原始文件只读保存位置：

## 4. 预处理与质量检查

- LocalGaze 入口：桌面单文件 / 桌面映射表 / 已核实的 API：
- preset：`analysis` / `legacy` / 其他有依据的方案：
- 时间单位及来源：
- 界面暴露的参数及取值：
- 映射表字段与路径基准：
- 缺失、坏段、可疑段和异常样本的处理规则及理由：
- 是否需要同步、重整、基线或单位转换；若需要，说明输入、输出、算法和参数来源：
- 质量检查输出及通过 / 失败判据：

## 5. ROI 与坐标

- ROI 形状、名称、优先级和几何来源：
- ROI 与 gaze 是否使用相同且已验证的坐标参考：
- 监视器、原点、分辨率、物理单位、DPI 和映射关系：
- 重叠 ROI、边界和被截断访问如何处理：
- 如果研究结局是 ROI 内注视时长，注视事件与 ROI 命中的组合定义及验证方式：

## 6. 指标与统计计划

- 描述性指标 / 事件候选 / ROI 指标：
- 每个指标的定义、单位、汇总层级和用途：
- 统计模型或检验及其与设计、推断单位、结局类型的对应关系：
- 缺失、排除、无效事件及拟合失败规则：
- 假设诊断、效应量、区间和敏感性分析：
- 多重检验家族与校正方法：
- 使用的库、版本和独立执行脚本：

LocalGaze 提供描述性指标与候选事件，不提供通用推断统计引擎。不得把 gaze 样本当作彼此独立的被试；需按实际分配单位建模或汇总。方法、排除规则和变换应在查看条件差异前确定。

## 7. 输出、环境和状态

- 新的空输出目录（必须与原始数据分开）：
- 预期配置、转换、QC、结果和日志文件：
- Python、操作系统、LocalGaze、依赖版本：
- 文件清单、哈希和保留期限：
- 尚缺的信息、责任人和下一步：
- 当前证据状态：`DRAFT` / `STRUCTURE_LOADABLE` / `ENGINEERING_DEMO_ONLY` / `REAL_PILOT_PASSED` / `REAL_EXECUTABLE`

结构可加载不等于方法经过科学验证，也不代表真实设备链路、GUI、统计脚本或真实结果已验证。未完成的步骤标为 `NOT_RUN`，不能写成已通过。
